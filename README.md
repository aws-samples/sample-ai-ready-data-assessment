An open-source **"AI-Ready Data" enterprise data-capability maturity self-assessment toolkit**. It helps an enterprise judge whether the data capabilities it has built and operates for AI scenarios have reached an "AI-Ready" level across six dimensions: **cost and value, data quality, platform operations, organization and talent, governance and trust, and security and compliance**.

- **45 questions**, spread across 6 dimensions, each a single choice from five options: A/B/C/D/N-A.
- The question bank is authored in **Markdown** (human-readable + machine-parsable) and decoupled from the scoring logic.
- **Scoring and maturity grading are computed automatically by a script** — with N/A exemptions, per-dimension get-rate, L1–L4 maturity levels, and D-tier ratio.

> The design follows common practices of public open-source maturity-assessment projects (such as OWASP SAMM / DSOMM): maintain the **model content** and the **scoring tool** separately, **version** the questionnaire to ensure comparability across versions, and use **different licenses** for content and code.

## Quick Start

### 1. Answer

Open each dimension file under `modules/` and, for every question, pick the option that best matches your enterprise's current state (A / B / C / D, or `N/A` if the capability/scenario does not currently exist).

Fill your answers into an answer file, in either of two formats. The quickest start is to copy a bundled example and overwrite the answers — it already contains all 45 rows with the correct ids:

```bash
cp scoring/answers.example.csv my-answers.csv     # then edit the answer column
```

**CSV** (three columns `dimension,question,answer`, see `scoring/answers.example.csv`):

```csv
dimension,question,answer
dim1,Q1,C
dim1,Q2,B
...
dim5,Q3,N/A
```

**JSON** (a nested object of dimension → question → answer, see `scoring/answers.example.json`):

```json
{
  "dim1": { "Q1": "C", "Q2": "B", "...": "..." },
  "dim5": { "Q3": "N/A" }
}
```

### 2. Score

The script depends only on the Python 3 standard library — nothing to install:

```bash
cd scoring
python3 score.py answers.example.csv      # or answers.example.json
```

> The report is in **English by default**. Use `--lang zh` for Chinese or `--lang both` for a bilingual (English / 中文) table; `--json` always carries labels for both locales so a downstream generator can render either language.

Common options:

```bash
python3 score.py answers.csv                           # English report (default)
python3 score.py answers.csv --lang zh                 # Chinese-only report
python3 score.py answers.csv --lang both               # bilingual report (English / 中文)
python3 score.py answers.csv --json                    # machine-readable JSON (carries both locales)
python3 score.py answers.csv --weights 1,1,1,1,2,2      # industry/stage weighting (e.g. finance weights governance & security more)
python3 score.py answers.csv --strict                  # error on unknown/missing questions instead of warning
python3 score.py --version                             # print the questionnaire version and exit
```

> **Every report carries the questionnaire version** (`questionnaire: v1.0.0`
> above; the `--json` output carries it as `questionnaire_version`). Keep it with
> the result: scores are only comparable within one questionnaire version, see
> [`SCORING.md`](./SCORING.md). The version is read from [`VERSION`](./VERSION).
>
> `--strict` turns every warning into an error, which covers an unknown
> dimension, a question count that does not match the dimension, a duplicate
> answer for one question, and a question id that does not exist in its
> dimension (`dim1,Q77,C` — `dim1` only has `Q1`–`Q6`). Use it in a pipeline;
> without it those problems are reported as warnings and scoring continues.

## Scoring Mechanism (Summary)

See [`SCORING.md`](./SCORING.md) for the full explanation.

**Per-question value**: `A=0` (not started), `B=1` (initial practice), `C=2` (basically compliant), `D=4` (mature and leading), `N/A` scores nothing and is excluded from the denominator.

> C→D is worth **2 points** (rather than an even 1 point) because A→B→C is a quantitative progression "from nothing, to some awareness, to a basically systematic approach," whereas C→D is a qualitative leap: "the system truly works end-to-end, is automated, and is continuously verifiable" — a steeper threshold. Amplifying this gap prevents "a few questions jumping to D from inflating the overall impression score."

**Get-rate** (dynamic denominator, handling N/A exemptions):

```
dimension get-rate = dimension score / (questions actually answered in that dimension × 4) × 100%
```

**Maturity grading** (the same set of bands is applied both to the overall result and to each dimension):

| Level | Get-rate band | Meaning |
|---|---|---|
| L1 Not Started | `[0%, 25%)` | Capability essentially absent |
| L2 Initial Practice | `[25%, 50%)` | Scattered practices, not yet systematic |
| L3 Basic | `[50%, 75%)` | Core mechanisms established, but gaps in automation/verification/closed loop |
| L4 Mature & Leading | `[75%, 100%]` | Systematic, automated, traceable, with a continuous-improvement closed loop |

**Special case**: if all answers in a dimension are N/A, that dimension has **no get-rate and does not participate in the radar-chart comparison**; the report marks it "not applicable" instead of showing 0% (showing 0% would be misread as "doing very poorly").

---

## How to Interpret the Results

- First read the **overall level** to locate your general standing, then read the **independent level of each dimension** to find weak spots — the total score masks structural imbalance (e.g. a very strong platform but a governance gap).
- Pay attention to the **D-tier ratio**: it shows, better than the get-rate does, "how much capability has truly reached a systematic + automated + verifiable closed loop," rather than a decent-looking score "averaged out" by a large number of C-tier answers.
- We recommend presenting results as a **radar chart** (six axes for the six dimensions' get-rates, 0–100%), which is comparable across dimensions.
